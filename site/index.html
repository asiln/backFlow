From the running app back to the design file.

The order used to be design first, build second. Now code changes every day. Backflow runs the other way: it measures what the browser rendered and hands design a file it can work in.

  1. Your app, running locally

    localhost:3000

    Use test accounts. The extractor refuses any other origin.

  2. Extract

    npx @backflow/cli extract screens.json

    Reads computed styles, geometry, text, SVG icons and images for each screen.

  3. Measured JSON

    screens.figma.json · tokens.json · _library.json

    Plus a report for every screen with what was lost and why.

  4. Figma plugin

    Tokens, then Components, then Screens. Each step previews before it changes the file.

  5. Design reviews

    Decisions flow back to the code.

Built for review, not for redrawing.

Run it again after every merge. Tokens and components are matched by key, so a new run updates the file instead of piling up duplicates. Designers look at what changed and decide.

Approved

It matches the intent. The change becomes the new reference in the file.

Revise

Close, but not right. The designer edits the frame and the fix goes back to the repo as a ticket or a PR comment.

Rejected

It shouldn't have shipped. Design has the evidence: the exact screen, values and component.

What lands in Figma.

A file a designer can keep working in. Layout holds when content changes, colours and type are variables, and repeated UI is components.

General notes.

The rules every drawing in this set follows.

  1. Local only.

    Extraction runs on your machine with Playwright, against localhost. No Figma API quota, no cloud upload.

  2. No network in Figma.

    The plugin declares no network access, so app data never leaves the file.

  3. Measured, not guessed.

    Every layout decision comes from what the browser rendered and is checked before it's trusted.

  4. Honest about loss.

    When fidelity drops, the container steps down a level, the import keeps going, and the report says where and why.

  5. Previews first.

    Tokens and Components preview every change before anything is written to the file.

  6. Old files keep working.

    New fields are optional. An export from an older version still imports.
